# 光模块公司财报问答知识库

把 12 家 A 股光模块 / 光通信公司的最新年报和半年报做成一个能问答的本地知识库：
**向量检索 + BM25 混合召回，答案逐条带公司、报告、页码、章节出处。**

不发一次 API 请求 —— 答案是从原文里摘出来的句子（外加少量能算的算一下），
所以每个数字都能顺着页码翻回去核对。

> `scripts/ask.py` 里保留了一个可选的大模型作答分支（要自己往 `.env` 里配 key 才启用，
> `.env` 已在 `.gitignore`）。本项目的评测、报告和截图**全部走抽取式后端**，
> 没有调用任何外部 API。

## 怎么跑

```bash
# 1. 依赖
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt

# 2. 抓报告（首次；已下载的会跳过）
python scripts/fetch_reports.py

# 3. 建索引：抽 PDF 正文 → 切块 → 向量化 → Chroma + BM25
python scripts/extract.py && python scripts/chunk.py && python scripts/build_index.py

# 4. 命令行提问
python scripts/ask.py "中际旭创2026年上半年营业收入是多少？"

# 5. 网页版（自动带出处高亮）
python scripts/app.py 8848     # → http://127.0.0.1:8848/?q=...
```

评测：

```bash
python eval/run_eval.py --k 8   # 跑 10 道题，写 eval/results.json
python eval/make_report.py      # → eval/report.md（逐题记录）
python shots.py                 # 截问答页面图 → shots/
```

## 结构

```
scripts/
  fetch_reports.py   巨潮资讯网抓 PDF
  extract.py         PDF → 文本（逐页，保留页码）
  chunk.py           切块：按章节/表格边界，带 company/report/section/page 元数据
  build_index.py     Qwen3-Embedding-0.6B 编码 → Chroma；jieba + BM25Okapi
  search.py          HybridSearcher：向量 / BM25 / RRF 融合、元数据预过滤、条目定位
  ask.py             答案层：路由 + 抽取式作答 + 计算 + 拒答
  app.py             网页问答界面（纯标准库 http.server）
eval/
  questions.json     10 道题 + 金标（公司/报告/页码）
  run_eval.py        跑评测：三路召回对比 + 全景覆盖 + 逐家对账
  make_report.py     results.json → report.md
  report.md          ★ 逐题记录：召回名次 / 逐家对账 / 答对没有 / 错在哪 / 怎么修
  results.json       原始评测结果
```

## 检索层

三路召回，取 top-k：

| 通道 | 做法 |
|---|---|
| 向量 | Qwen3-Embedding-0.6B（1024 维，`max_seq_length=1024`）→ Chroma，cosine |
| BM25 | jieba `cut_for_search` 分词 + BM25Okapi，索引落盘 `data/bm25.pkl` |
| 融合 | RRF，`k=60`，两路各取 30 个候选 |

再加**元数据预过滤**：问句里识别出公司名和报告期，检索前把候选锁到对应文档
（「半年度」要在「年度」之前判 —— 「半年度」三个字里就含「年度」）。
另有两条按需启用的**定位通道**：`$contains="主要会计数据"` 直接捞可比口径的表、
`$contains="主营业务"` 直接捞章节标题。

## 答案层

没有大模型，答案靠四步拼出来：

1. **拒答守卫**：问句里的实体不在库里（如「宁德时代」）→ 直接说明库里有什么，不给数字。
2. **路由**：跨公司排名题走逐公司枚举；否则走向量+BM25 融合检索。
3. **抽取**：按「与问句的词重叠 + 名次 + 句长」给句子打分，再扣掉勾选框、表头、
   母公司列、章节标题、纯公司名命中这些干扰项。
4. **计算**：问毛利率这类需要算的，显式给出算式，两个数取自同一个块。

细节上处理的坑：**单位**（德科立整份报告是千元，其余 11 家是元）、
**合并 vs 母公司**（新易盛母公司营业收入反而比合并数大）、
**PDF 断行**（`24,841,854,840. 22` 小数点后嵌空格；句子被硬换行切成两半）、
**同一公司年报/半年报两份**（取错就是 119 亿 vs 66 亿的区别）。

## 结果

10 道题（5 类：精确数字 / 语义 / 表格计算 / 跨公司全景 / 应拒答），
逐题明细见 [`eval/report.md`](eval/report.md)。

| 题 | 类型 | 三路召回的混合最好成绩 | 最终作答 |
|---|---|---|---|
| Q1 | 精确数字（新易盛 26H1 营收） | #3 | 答对，首条即金标行 |
| Q2 | 原因/语义（中际旭创增长原因） | 未命中 | 答对 |
| Q3 | 表格+计算（太辰光毛利率） | #1 | 答对，算出 34.81% |
| Q4 | ★单位陷阱（德科立千元） | #1 | 答对，答出 545,069.47 千元 |
| Q5 | ★跨公司增速排名 | 3/12 家 | 答对，12/12 家取到数 |
| Q6 | ★跨公司规模排名 | 5/12 家 | 答对，12/12 家取到数 |
| Q7 | 年报 vs 半年报 | 未命中 | 答对（119.29 亿） |
| Q8 | 定性·双主业 | 未命中 | 答对，但首句不理想 |
| Q9 | ★数字完整性（断行数字） | #1 | 答对（248.42 亿） |
| Q10 | ★应拒答 | — | 拒答正确 |

**最值得记的一条结论**：跨公司题上，单次检索（不管哪一路）只能覆盖 3–5/12 家 ——
把 12 份财报放进同一个向量库，稠密检索并不会「自动帮你收齐」。
必须换成逐公司枚举 + 表头词定位，才能 12/12。

## 已知短板（如实记）

- **Q8 首句不理想**：正确句排在第 2 条，第 1 条是「行业情况未发生重大变化」这类泛泛句。
- **拒答守卫是启发式**：靠公司名后缀（公司/集团/科技/时代…）识别库外实体。
  英文名（`Coherent`）或简称（`宁王`）会漏判，届时可能拿库里某家的数字作答。
- **Q9 是绕开不是堵住**：引用的是原文里完整写出的叙述句；若某口径只在被 PDF 切断的
  表格里出现，仍会踩到断行数字。
- 部分答案在正确句之后还跟几条同表的噪声行（多给，不是答错）。
