代码仓库（公开）：https://github.com/jinyanxiaonku6/earnings-rag

这次交的是什么：把 12 家 A 股光模块 / 光通信公司的 2025 年度报告 + 2026 半年度报告 （共 24 份，全部取自巨潮资讯网公开披露文件）做成一个能问答的本地知识库 —— 向量检索 + BM25 混合召回（RRF），答案从原文摘句、逐条带「公司 / 报告 / 章节 / 页码」出处。 10 道评测题（含 2 道跨公司全景题、1 道应拒答题），10/10 作答正确，召回与作答分开评价。

抓取、抽文本、切块、向量化、BM25、融合、作答、评测的全部实现都在本仓库内 （scripts/ 8 个文件 + eval/ 5 个文件 + data/manifest.json，初始提交 fa940fe，共 24 个文件）。 作业1 的前端源码仓与本作业无关，本作业没有复用它的任何代码。

二、召回命中 与 答题正确 是分开评价的

对应第三课 61–63（召回评估）与 90–92（生成/作答评估）、163（实验记录）三处要求，本项目把两层指标 拆开、并列展示，不合并成一个总分：

召回层（eval/report.md 的「汇总」表，只记名次/覆盖数，与答案对错无关）

  • 单公司题记 金标块名次：命中判定 = 检索结果里出现「金标公司 + 金标报告 + 金标页 ±1 页」的块；
  • 跨公司全景题记 覆盖家数（12 家中召回了几家）；
  • 五列对照：向量 / BM25 / 混合 / 混合(关掉元数据预过滤) / 全景枚举。
  • 结论：单次检索在跨公司题上只覆盖 3–5 / 12 家（三路都一样，融合有时是负贡献）； 换成「逐公司枚举 + $contains="主要会计数据" 表头词定位」后 12/12。

作答层（每题「判定」段）

  • 写清「答对 / 答错」、答案数值、以及证据出处（公司+报告+页码）；
  • 答错或答得不理想的照写不删：Q8 首句不理想（正确句排在第 2 条）、 拒答守卫是启发式（英文名/简称会漏判）、Q9 是绕开不是堵住， 三条都进了 README「已知短板」。

两层不同步的例子（正说明必须分开看）：Q2 / Q7 / Q8 三路混合检索都没命中金标块， 但最终作答仍答对 —— 因为答案层走了「逐公司枚举 / 表头词定位 / 摘句打分」另一条路。 若把召回和作答揉成一个分数，这三题既算不清也对不上账。

四、怎么复跑出以上材料

python -m venv .venv && .venv/Scripts/pip install -r requirements.txt

python scripts/fetch_reports.py                                  # 按 manifest 抓 24 份 PDF

python scripts/extract.py && python scripts/chunk.py && python scripts/build_index.py

python eval/run_eval.py --k 8      # → eval/results.json（10 题三路召回 + 作答）

python eval/make_report.py         # → eval/report.md（逐题记录）

python scripts/ask.py "中际旭创2026年上半年营业收入是多少？"

python scripts/app.py 8848         # 网页版 → http://127.0.0.1:8848/?q=...

本次复跑输出见 eval/run_2026-10-12.txt；作答不调用任何外部 API（.env 未配置，也不在仓库里）。
